# HomeDrive v0.2 — first working slice

HomeDrive now supports authenticated folder listing and creation, streaming file upload, and download. There is no fixed per-file size cap; available filesystem space and filesystem/browser limits determine what fits. It stores files under `<HOMEOS_DATA_DIR>/files` (or `backend/data/files` for the default native setup). The Go server and Docker deployment use the same persistent data directory as SQLite. Existing files are never overwritten by an upload.

All Drive API routes require a valid administrator session. Folder creation and upload also require the session's CSRF token. Paths are relative to the Drive root; absolute paths, `..`, Windows device names, and symlink traversal are rejected. The server uses Go's filesystem-root API to keep operations within the Drive directory.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/v1/drive?path=folder` | List the root or a folder. |
| `POST` | `/api/v1/drive/folders` | Create a folder; JSON body `{ "path": "folder/new" }`. |
| `PUT` | `/api/v1/drive/files?path=folder/name.ext` | Upload the raw request body to a new file. |
| `GET` | `/api/v1/drive/files?path=folder/name.ext` | Download a file as an attachment. |

This is an initial slice, **not yet a replacement for Nextcloud**. Deletion, rename/move, sharing, previews, version history, quotas, multi-user permissions, upload progress, and resumable uploads are not implemented. Large uploads must finish in one browser session and restart from zero if interrupted. An in-progress upload may be visible until it completes; failed uploads are removed. Downloads use a direct HTTP attachment, so the browser does not buffer the entire file in the page. Do not use HomeDrive as the only copy of important files yet.

## Backup

The SQLite backup command backs up the database **only**. Back up the `files` directory separately, preferably after stopping uploads, and restore it together with the matching SQLite snapshot. Keep an independent copy outside the HomeOS host before using Drive for valuable data. Do not commit `backend/data/files` or any backup to Git.
