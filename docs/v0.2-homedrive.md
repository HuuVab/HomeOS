# HomeDrive v0.2 — first working slice

HomeDrive supports authenticated folder listing and creation, streaming file upload, and download. The default per-file limit is 2 GiB and the default per-user quota is 20 GiB. Set `HOMEOS_MAX_FILE_BYTES` and `HOMEOS_USER_QUOTA_BYTES` to positive byte counts before starting the server to change them. Both direct and resumable uploads stage bytes in a hidden directory and publish the finished file with an atomic rename. Existing files are never overwritten by an upload. HomeDrive stores files under `<HOMEOS_DATA_DIR>/files` (or `backend/data/files` for the default native setup). The Go server and Docker deployment use the same persistent data directory as SQLite.

All Drive API routes require a valid user session and are scoped to that user's storage root. Mutating operations also require the session's CSRF token. Paths are relative to the user's Drive root; absolute paths, `..`, Windows device names, and symlink traversal are rejected. The server uses Go's filesystem-root API to keep operations within the Drive directory.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/v1/drive?path=folder` | List the root or a folder. |
| `POST` | `/api/v1/drive/folders` | Create a folder; JSON body `{ "path": "folder/new" }`. |
| `PUT` | `/api/v1/drive/files?path=folder/name.ext` | Upload the raw request body to a new file. |
| `GET` | `/api/v1/drive/files?path=folder/name.ext` | Download a file as an attachment. |
| `POST` | `/api/v1/drive/uploads` | Start or resume an upload; JSON `{ "path": "folder/name.ext", "size": 123, "fingerprint": "64 hex characters" }`. Returns the session ID and current offset. |
| `PATCH` | `/api/v1/drive/uploads/{id}` | Append a raw chunk (maximum 8 MiB) with `X-Upload-Offset`. Returns the new offset. |
| `POST` | `/api/v1/drive/uploads/{id}/complete` | Verify the declared size and make the file visible. |

This is an initial slice, **not yet a replacement for Nextcloud**. Sharing, previews, version history, quotas, and multi-user permissions are not implemented. The browser supports rename, move, Trash, restore, and permanent deletion. It shows chunk-level upload progress. After interruption or a browser/server restart, select the same file and click Resume; the server checks the path, size, and SHA-256 fingerprint of its first/last 64 KiB before returning the saved offset. Incomplete files are hidden from HomeDrive listing and download, though they occupy disk space and can be seen directly on the host filesystem. Abandoned uploads are not yet automatically cleaned up. Downloads use a direct HTTP attachment, so the browser does not buffer the entire file in the page. Do not use HomeDrive as the only copy of important files yet.

## Backup

An administrator can create another account with `go run ./cmd/homeos create-user <username>` from the backend directory (or `/app/homeos create-user <username>` in the container). The command prompts for a password. Each account has its own HomeDrive storage root; existing files remain with the original administrator. The `file_entries` SQLite table records each owner's visible file metadata and is refreshed after file operations and at startup for the original administrator. Back up SQLite and the file tree together.

Trash items can be restored or permanently deleted in the browser. The server permanently removes items after 30 days by default, checking at startup and every 24 hours. Set `HOMEOS_TRASH_RETENTION_DAYS` to a positive integer before starting the server to change the retention period. Permanent deletion cannot be undone; keep independent backups.

The SQLite backup command backs up the database **only**. Back up the `files` directory separately, preferably after stopping uploads, and restore it together with the matching SQLite snapshot. Keep an independent copy outside the HomeOS host before using Drive for valuable data. Do not commit `backend/data/files` or any backup to Git.
